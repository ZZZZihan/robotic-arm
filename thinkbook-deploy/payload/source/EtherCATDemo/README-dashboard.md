# 四轴操作台 · 使能保险版 — 2026-10-09

完整交接、Windows 构建与版本切换入口见[根 README](../../../../README.md)；手册、固定版本 SDK 与原始示例见[资料目录](../../../../materials/README.md)。本文集中说明当前界面和修复行为。

修复圈数/转速键盘输入被界面刷新提前格式化的问题。可直接输入整数、小数，也可 Ctrl+A 全选重填；回车只确认输入，不启动运动。输入框旁的上下按钮仍可微调。空白、非数字或超范围输入会显示提示并禁止轴2新运动，不会悄悄改成范围上限或使用旧值。

本版以四张状态卡片选择软件轴1、2、3、4，卡片索引仍对应SDK轴号1、2、3、4。用户已在现场确认轴2正向向上、反向向下，界面对应“↑ 上升 · 正向”和“↓ 下降 · 反向”。方向按钮沿用原正负指令，没有反转电机或改写驱动参数。选轴卡片只改变选择，不连接、不使能、不运动。

主区域显示当前轴操作，右侧显示电机编码器位置、规划位置、两者差和状态。轴2用电机圈数相对移动，初始圈数为0，转速默认120转/分钟，输入和运动前检查沿用圈数测试版。“走多少”填写电机圈数，“走多快”填写转/分钟；输入后预览目标圈/秒和含加减速的预计时间。短行程可能达不到目标转速。编码器计数和电机圈数不等于升降高度，尚未设置毫米换算。轴1、3、4保留原来的点动与绝对定位速度、目标、加减速。状态卡片和反馈均来自现有状态采样，不额外轮询SDK。

打开 App 后自动连接控制卡并检查总线。已有4个从站且初始化站号为0时沿用现有总线，不重复初始化；确为0个从站、四轴未使能且静止无报警/限位时，只提交一次总线初始化，至少等待1秒并核对4个从站和新的四轴静止反馈，15秒未完成则锁定运动。连接、总线和维护输出按钮已移除，状态保留在诊断页。启动不会自动使能或运动。

## 打开与操作

1. 在四轴停止、升降负载可靠保持时正常关闭旧控制程序，再打开桌面“机械臂-四轴操作台”。不要同时运行多个控制程序。
2. 打开后等待自动连接和总线检查完成；查看新的四轴反馈及诊断页状态。部分从站、读取失败、报警/限位或运动中的设备会锁定启动，不自动重复初始化或清故障。
3. 选择轴卡片，点击顶部唯一的“使能保险”；仅对当前轴发使能请求，等新的使能反馈后放行运动。切换轴、反馈中断、失能或报警/限位会撤销本次授权，必须再次人工打开保险。轴2填写本次电机圈数和转速，确认可用行程后点击“↑ 上升”或“↓ 下降”；轴1、3、4按住点动、松开停止，定位仍是固定绝对目标计数。
4. 顶部红色“急停”始终可点，不弹确认框，不受输入错误或反馈失效限制。先锁定保险，再请求停止全部轴和坐标系；成功返回也须确认现场机械停止。软件急停保持伺服持力，不直接断使能，以免未经验证的升降抱闸失去保持。急停后不自动恢复；停止请求成功、新鲜静止反馈和总线核验通过后，人工点击“重新打开保险”才能继续。软件急停依赖控制通信，现场物理急停仍须可用。
5. 原有“停止轴2”保留为普通停止；其他轴普通停止仍是全轴停止。普通停止不会自动撤销仍有效的保险；急停会锁存保险。

检测到轴规划运动时锁定选轴，待停止反馈后恢复。停止请求返回成功不等于实际机械停止；未使能、报警/限位、跟随差过大等启动拦截仍保留。

## 2026-10-09 现场修复与检查记录

用户报告停止轴2后无法再驱动，随后说明切回原控制卡也不能驱动。早期换卡期间的授权只读检查得到从站数量0、初始化站号-1；这不能代表当时连接在原控制卡上的驱动状态。后续日志显示电机编码器随指令变化，但不能据此断言升降机构同步移动。

用户随后明确反馈“修好了，是螺旋杆脱落了”，并确认轴2正向向上、逆向向下。本版按该现场确认更新操作台。机械修复由用户确认，软件侧未进行新的实机动作验收；没有据此修改零点、使能流程或速度上限。

本版增加：

- 停止请求发出前、返回后分别记录日志；启动前记录四轴状态及轴2规划/反馈位置。
- 通信错误-1/-7增加中文解释；采样恢复时更新提示，避免旧错误永久留在操作提示中。
- 反馈中断后废弃上一次运动的圈数显示基准，避免控制器位置重建后显示错误的跨会话增量。
- 未获得有效反馈时禁止使能、定量定位和维护输出；点动起步也检查反馈有效，停止入口保持可用。
- 保留停止、未使能、跟随差与报警等原检查，不自动清故障、修改零点或重新启动运动。
