## 1. 版本与配置

当前维护入口是 `thinkbook-deploy/payload/source/EtherCATDemo/CSharpDemo.csproj`，Windows WinForms、.NET Framework 4.0 Client Profile、x64。应用代码基线 `ac636ff`；目录名仍沿用厂商 Demo，不表示里面还是原版。程序集版本号仍为 `1.0.0.0`，辨别现场版本应结合窗口标题、实际 EXE 路径、文件哈希及交付记录。

| 项目 | 当前已知 | 仍需记录/确认 |
| --- | --- | --- |
| 控制卡 | 博派 EtherCAT 控制卡；使用配套 MultiCard SDK | 现场序列号、固件版本及对应参数备份 |
| 驱动器 | 用户确认升降驱动器为汇川 SV630N；软件预期四个从站 | 四台完整型号、线缆、站序与实体轴对应表 |
| 软件轴2 | 丝杆升降；正向上升，反向下降 | 导程、机械传动比、上下实际行程及原点 |
| 软件轴1、3、4 | 操作者反馈可运动，保留原 Demo 控制方式 | 各自实体名称、正负方向与完整机械限位 |
| 轴2电机换算 | 软件要求 H00.00 代码 14101、262144 计数/电机圈、电子齿轮和卡端比例均 1:1 | 电机更换或参数变更后重新核对 |
| 控制网络 | 当前 `Form1.cs` 使用 PC `192.168.0.200`、控制卡 `192.168.0.1`，UDP 60000 | 当天专用网卡地址、路由和独占程序 |

上表的控制网络地址是代码里的设备端点，不是 SSH 登录地址。账号、SSH 密钥、远程运维连接信息不放入此仓库；交接时由设备管理员通过合适渠道提供。构建不需要 SSH，也不需要修改网卡。

此前曾根据静止数值猜测另一个软件轴是升降轴，该猜测已被现场说明纠正。**本版操作对象始终是软件轴2；不要把升降方向改到轴3。**

## 3. 轴2启动、停止与反馈语义

一次轴2启动会检查：输入范围；四轴无运动或报警/限位状态；轴2使能；静止规划—编码器差不超过 100 计数；四从站数量；卡端比例；驱动电机代码、电子齿轮、CSP 模式、错误码与运行使能状态；抱闸延时读数和使能稳定时间；预检期间位置稳定及驱动/卡反馈一致；预检超时；目标 32 位范围。

检查通过后，用新读到的规划位置加本次增量，调用 `GA_SetTrapPosAndUpdate(2, ...)`。加减速沿用 `1 count/ms²`。上述检查发生在程序和通信层，不证明实际抱闸线路、承载能力和独立急停链已合格。

运行中不允许给轴2叠加新指令；状态更新会监测异常及超时。当前程序还有以下行为：

- 手动停止轴2使用 `GA_Stop(2, 2)`，停止请求不会主动断使能。
- 停止请求返回 0 后仍需等待有效状态显示规划停止，不能立即宣称机械停止。
- 窗口失去焦点时，若轴2任务处于活动状态，会请求停止。关闭窗口也会先请求停止并暂时取消关闭。
- 有效停止反馈到来后，可显式再次启动；下一次以新读到的位置计算相对目标，不沿用被中断目标。
- 反馈丢失时使本次圈数基准失效，旧累计值不继续显示为可信增量。
- 规划完成的判定主要使用规划位置与运行位；它不等于独立测量的机械到位确认。

**轴1、3、4是保留的旧路径**：JOG 起步仍会调用 `GA_AxisOn`，JOG/绝对定位的 SDK 返回码处理也没有全部提升到轴2同等程度；点动松开调用全轴停止。不要把轴2的完整预检承诺推广到其他三轴。这是下一轮维护的具体风险项，不是本次已完成的统一控制层。

## 4. 如何取证排障

应用日志在所运行 EXE 旁的 `logs/axis2-<时间戳>.log`。日志文件名是程序启动时建立的本地时间标识，行首时间使用 UTC；界面操作记录用本地时间。排障时注明时区。

| 标记 | 记录了什么 | 能说明什么 |
| --- | --- | --- |
| `PREFLIGHT` | 四轴状态、轴2规划和编码器位置 | 发令前采样，不能说明后续机械移动 |
| `COMMAND` | 轴2目标计数和 `velocityPulsePerMs` | 请求下发的目标；同时检查后续错误信息 |
| `SAMPLE` | 运行时规划、编码器、状态 | 通信采样的跟随情况，不是升降高度传感器 |
| `STOP` | 请求时是否活动、停止 API 返回码 | 停止请求结果，仍需后续状态及现场观察 |
| 中文错误/恢复提示 | 通信错误、预检拒绝、恢复等 | 必须与对应时间和实际版本一起解释 |

最小故障记录：实际 EXE 路径/哈希、轴号、输入圈数和转速、方向、日志时间段、面板状态/错误码、现场是否有电机/机构运动、是否刚换过控制卡或接线。先复制记录，再决定下一步检查；不要先重置零点、清错、初始化或反复使能，把原始状态抹掉。

已遇到的两类轴2问题应分开：早期运动速度太低，视觉上难以看出升降；后来操作者确认丝杆脱落，编码器变化但机械不升降。它们不能作为以后所有“不动”的默认原因，更不能单凭无声音判定电机烧毁。

## 5. 软件交付与回滚

使用 [`build-dashboard.ps1`](../thinkbook-deploy/scripts/build-dashboard.ps1) 构建。每次输出包含完整 `app`、源码快照和验证结果，不改维护源码、不改运行中的程序、不调用设备。构建与离线检查不要求关闭正在运行的控制程序；真正切换控制程序时再由现场操作者停稳并正常关闭旧版本。

当前已交付的输入修复版路径和哈希见根 README。其上一个四轴方向版为 `four-axis-lift-20261009-134342`，再早的圈数测试版为 `axis2-turns-20261009-122203`，均位于 ThinkBook 的 `C:\RobotArmDemo\releases\`。这些是历史交付目录，是否还存在应现场核对。

回滚需要整组保留 EXE 与三份 SDK DLL。不要从另一套示例中只替换一个同名 DLL，也不要用原始厂商 Demo 替代当前维护源码后继续声称通过了本版检查。
