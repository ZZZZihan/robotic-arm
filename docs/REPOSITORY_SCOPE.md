# Repository scope

## Why this repository is private

当前工作区包含厂商手册、示例源码、运行库和现场部署记录。首版 GitHub 仓库按私有仓库建立，直到源码/资料的再分发许可和现场信息脱敏边界被单独确认。

## Tracked versus local-only

| 类别 | 首版处理 | 原因 |
| --- | --- | --- |
| 自己维护的源码、构建脚本、测试说明 | 跟踪 | 需要跨设备同步和审查 |
| 资源索引与用途说明 | 跟踪 | 让后续工作知道本机有哪些输入资料 |
| 原始 RAR/ZIP、完整解包目录 | 仅本机 | 文件大、重复多，且来源/授权需单独确认 |
| PDF、DLL、EXE、静态库和编译缓存 | 仅本机 | 生成物/第三方交付物，不作为首版源码依赖提交 |
| SSH/tailnet 连接信息、设备网络配置、网络前后状态、现场截图 | 仅本机 | 避免把运行环境和敏感现场信息带入远端 |

当前保留下来的示例源码可能包含供应商 demo 原有的控制器端点常量。这些值不是账户凭据，但仍按私有开发资料处理；新代码应从配置读取，公开发布前重新脱敏和确认授权。

## Adding a new artifact

新增同步文件前，先回答四个问题：

1. 它是源码/测试输入，还是可重新生成的产物？
2. 是否有厂商或第三方再分发限制？
3. 是否包含密钥、账户、内部地址、设备参数或现场照片？
4. 是否超过 GitHub 普通文件大小限制，或更适合用外部制品存储？

若答案不明确，先放在被忽略的本地资料目录，并在索引中记录用途，不直接 `git add -f`。
